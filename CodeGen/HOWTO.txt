Generated inverse kinematics code
=================================

IKBT writes the closed-form IK solution as both Python and C++.  Everything in
Python/ and Cpp/ is a GENERATED artifact and is overwritten by the next solve.


Python  --  Python/IK_equations<Robot>.py
------------------------------------------

A runnable, importable module.  It defines

    ikin_<Robot>(T)      goal pose T (4x4 numpy) -> list of joint vectors,
                         or False if the pose is unreachable
    JOINT_NAMES          the joints, in CHAIN order, matching each vector
    AUX_NAMES            sum-of-angle intermediates (computed, not returned)

and carries a __main__ that solves one sample pose, so

    python3 Python/IK_equations<Robot>.py

runs as a self-check.  Parameter values (link lengths etc.) are declared at
module level, so a caller can inspect or override them.

The module tests the domain of arccos() and arcsin() before calling them and
reports an unreachable pose rather than raising.


Python, HYBRID robots  --  Python/IK_hybrid_<Robot>.py
-------------------------------------------------------

For an arm IKBT cannot solve symbolically, see the two-phase module and its
sibling FK modules.  Phase I enumerates postures of a SIMPLIFIED arm; Phase IIa
refines one of them numerically against the TRUE arm.  The module's own
docstrings carry the details, and the LaTeX report names every file.


C++  --  Cpp/
--------------

Every Python artifact above has a C++ twin, written at the same time, from the
same solution, by a generator derived from the Python one.  The two are checked
against each other branch for branch by

    python3 -m scripts.cpp_closed_loop_check --gate

ONE FILE PER ROBOT.  Everything a solve emits for <Robot> -- FK, Jacobian, and
whichever IK the solver found -- is in

    Cpp/<Robot>CppCode/<Robot>.cpp          inside namespace ikbt::<Robot>

and the string SOLUTION_PATH in it says which of the three paths produced it:

    "symbolic"   ikin(T)                          every posture, closed form
    "onevar"     solve(T)                         a 1-D search over one variable
    "hybrid"     ikin_approx(T), refine_seed(T,q) seeds, then a numerical fix

IKdocs/CPP_API.md is the full reference, with a compiled example per path.

C++17, AND EIGEN, WHICH SHIPS WITH IKBT.  A pose is an Eigen::Matrix4d (Mat4),
a joint vector an Eigen::VectorXd (JointVec).  Eigen is header-only and a copy
is vendored in Cpp_src/third_party/eigen3/, so there is nothing to install, no
build system and no include path:

    g++ -std=c++17 -O2 -c Cpp/<Robot>CppCode/<Robot>.cpp

Define IKBT_SYSTEM_EIGEN to use your own Eigen instead of the vendored copy.

The shared material in Cpp_src/ is reached by a relative #include,

    #include "../../../Cpp_src/ikbt_types.h"

so there is ONE copy of it for the whole package and a fix to it needs no
regeneration.  `#include "..."` resolves against the including file's own
directory, which is why no -I is needed.

KEEP THE DIRECTORY WHERE IT IS relative to Cpp_src/.  To build somewhere else,
copy Cpp_src/ along with it and keep the same three levels between them, or
edit the relative path.

Every file carries a self-test behind #ifdef IKBT_MAIN, which is the C++
spelling of `if __name__ == "__main__":`:

    g++ -std=c++17 -O2 -DIKBT_MAIN Cpp/<Robot>CppCode/<Robot>.cpp -o ik && ./ik

It is behind an #ifdef and not unconditional so that a generated file can be
linked into a program, or alongside another robot, without two main()s.

A PARAMETER WITH NO VALUE STOPS THE COMPILE, deliberately.  If the robot's
pvals has no entry for a link length, it is emitted as

    const double d_1 = XXXXX;   // USER MUST supply a numerical value here

so g++ stops with "'XXXXX' was not declared in this scope" and names the line,
and a missing dimension cannot be silently defaulted to something wrong.
Supply your values and it compiles.  Parameters the robot DOES have values for
are baked in, exactly as in the Python -- so most robots compile as they stand.


Cpp_src/  --  where the shared C++ comes from
-----------------------------------------------

Cpp_src/ is SOURCE, not a generated artifact, on the same footing as
LaTex_src/: hand-written headers (types, pose error, damped least squares, the
1-D search, and a vendored Eigen) that generated files reach by a relative
#include.  They are also
independently compilable, which is why they are files and not strings in the
generator -- the numerics can be unit-tested as C++.
